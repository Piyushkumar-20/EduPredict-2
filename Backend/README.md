# EduPredict AI — Synthetic 10-Point Benchmark

This is a complete development benchmark for a student support classification project. All 5,000 records are synthetic and generated by code; they are not real students.

## Label rule
`High Risk` is generated from synthetic academic indicators (very low GPA or combinations of low GPA, course grade, assignment submission and engagement). Attendance is excluded from the classifier and handled by a separate alert at 65%.
These thresholds are illustrative and must be approved/changed by faculty before real use. Since labels are generated from a rule, high test metrics measure reproduction of that rule—not validated real-world predictive performance.

## Run on Windows PowerShell
```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
# Copy .env.example to .env and fill in your MySQL/Gemini credentials
python run_backend.py
```
Set `BACKEND_PORT` in the project root `.env` to choose the backend port. Open `http://127.0.0.1:<BACKEND_PORT>/docs`.

## Retrain
```powershell
python train_model.py --data data/EduPredict_Synthetic_Benchmark_5000.csv --out artifacts
```

## API schema
- `GPA`: 0–10, college's 10-point scale
- `attendance_rate`: fraction from 0 to 1 (e.g. 0.84 = 84%)
- assignment/video rates: fraction from 0 to 1
- `avg_course_grade`: 0–100
- do not pass `attendance_percent` or `GPA_10_scale_equivalent`; API derives attendance percentage and rejects redundant fields

## Included
- 5,000-row synthetic benchmark
- training script compares Logistic Regression, Decision Tree, Random Forest
- saved model pipeline
- metrics and confusion matrix
- FastAPI endpoints: `/health`, `/model-info`, `/predict`, `/predict-batch`
- faculty guide and schema

## Ethical and scientific limitation
Synthetic data lets you build and demo software without college records, but it cannot substitute for real validation. Don't report its metrics as proof of real-world student-risk accuracy.


## Updated risk interpretation
The classifier is trained on synthetic labels based on academic indicators only. Attendance is deliberately excluded from the model feature set; it is returned as a separate alert when attendance is at or below 65%. A student with strong CGPA, course grade and assignment/engagement indicators should not be automatically marked High Risk solely because attendance is low. This is still a synthetic demonstration model, not a validated model for real student decisions.


## MySQL persistence (Windows)

1. In MySQL Workbench, connect to your local MySQL server and run:

```sql
CREATE DATABASE IF NOT EXISTS edupredict CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

2. Install backend dependencies in the project root:

```powershell
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
# Copy .env.example to .env and fill in your MySQL/Gemini credentials
```

3. Set the connection variables in the same PowerShell terminal (use your actual MySQL username/password; do not commit credentials):

```powershell
$env:MYSQL_HOST="127.0.0.1"
$env:MYSQL_PORT="3306"
$env:MYSQL_USER="root"
$env:MYSQL_PASSWORD="YOUR_MYSQL_PASSWORD"
$env:MYSQL_DATABASE="edupredict"
python run_backend.py
```

The backend creates the `students` table automatically on startup. Check `http://127.0.0.1:<BACKEND_PORT>/health`; `database_connected` should be true. If false, inspect `database_error`, verify the MySQL service, port, username, password and database name.

4. In a second terminal:

```powershell
cd Frontend
npm install
npm run build
npm run dev
```

Set `FRONTEND_PORT` in `Frontend/.env` to choose the frontend port. If you change the backend port, update `VITE_API_BASE_URL` in `Frontend/.env` to match it.

The frontend loads stored records from `GET /students`. After CSV batch assessment, it saves results through `POST /students/bulk`. Existing `student_id` values are updated using MySQL upsert logic. The 10 original React sample records remain demo-only unless they are imported explicitly.

### Endpoints
- `GET /health` — model and MySQL connection status
- `GET /students` — saved students
- `POST /students/bulk` — upsert assessed student records (max 500)
- `POST /predict`, `POST /predict-batch` — model assessment

**Security:** never put MySQL credentials in frontend `.env`/Vite variables; they belong only in the backend environment. Use a dedicated database user with privileges only on `edupredict` for non-local deployment.


## Google Gemini personalized recommendations

The Recommendations workspace calls `POST /recommendations`. The backend runs the existing classifier first, then asks Google Gemini for supportive guidance. The classifier's academic prediction is not changed by Gemini, and attendance remains a separate alert. Generated recommendations are saved in the MySQL `student_recommendations` table. The Student Directory profile's **Generate AI suggestions** action requests a plan for that student.

1. Create a Google Gemini API key in Google AI Studio.
2. Install the added backend dependency: `python -m pip install -r requirements.txt`.
3. In the same PowerShell terminal used to start FastAPI, set the key (never paste it into React/Vite files or commit it):

```powershell
$env:GEMINI_API_KEY="YOUR_GEMINI_API_KEY"
$env:GEMINI_MODEL="gemini-2.5-flash"
python run_backend.py
```

The database initializer creates `student_recommendations` automatically on startup. Use `GET /students/{student_id}/recommendations` to read the most recent 20 saved plans. If the Gemini key is missing, the endpoint returns HTTP 503 rather than pretending a generated response exists. Provider failures return HTTP 502. Review all guidance before sharing; the classifier is trained on synthetic benchmark data and is not validated for real-world student decisions.


## Personalized Gemini recommendation updates

The Recommendations page now asks Gemini for a student-specific plan grounded in the student's actual academic indicators, major, reported skills, interests, projects, and career goal. The prompt explicitly differentiates actions for low grades, assignment completion, video completion, and strong performance; it prohibits invented course-level facts; keeps attendance support separate from the academic classifier; and requests a 7-day plan with measurable targets and follow-up measures.

Generated plans continue to be stored in the MySQL `student_recommendations` table. On the Recommendations page, use **Saved plans** to retrieve a student's latest saved plans, then select a history entry to display it. The recommendation output is formatted into readable section headings and bullets.

After updating files, install frontend dependencies with `npm ci` from `Frontend`, then verify using `npm run build`. Backend Python syntax can be checked with `python -m py_compile app.py`. A successful build/live Gemini request must be verified in the user's local environment; this archive has not been live-tested against a Gemini API key.

## Personalized AI plans
Gemini generates a Recovery Plan for students classified High Risk and a Growth Plan for students classified Safe. Plans include evidence-linked actions, a 7-day schedule, measurable targets, teacher support, and follow-up measures. Attendance follow-up remains separate from academic classification.
